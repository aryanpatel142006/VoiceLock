# Target-speaker extraction and same-gender overlap tricks for the live demo (T-317)

Research only, written 2026-10-10 from web pages read that day (links inline). Nothing was downloaded, installed, run or measured here; every "gain" below is the cited source's number on its own data, not ours. Items marked **(unverified)** were not confirmed from a primary page. Not repeated: the REAL-TSE / WeSep BSRNN checkpoint gate (`CONDITIONED_TSE_FEASIBILITY.md`), ECAPA crop-length/contamination margins, profile learning curve (T-201), oracle diagnostic (T-200/T-206), SepFormer trial.

## 0. What the repo already does (so these are extensions, not new)

`hearing/tse/windowed.py` overlap-adds windows with a raised-cosine crossfade. `hearing/tse/enrolled.py` already has: `margin` hysteresis (MARGIN 0.1 cosine, x4 in LDA units) that holds the previous window's stream when the top-2 score lead is below it; `_follow_hop` waveform-correlation matching of the previous output against the new window's streams (the same idea as CSS permutation alignment below); pause `hold` (capped by `pause_max_s`); F0 veto; LDA vs negative profile; `confidence` into the mixer. Gaps that remain: the hold only fires when the **current** window's margin is small and remembers one window; a confident-but-wrong window flips the stream at once; each pick embeds only the 1.0 s window stream; both streams are not tracked as continuous speakers across hops. Evidence the gap is selection, not separation: T-069 male-male at 1 s context: accuracy .742, wrong 1.75 s per 10 s vs candidate ceiling .930; at 2 s .804 / 1.34 s vs .951 (`CONDITIONED_TSE_FEASIBILITY.md` §4, `docs/BENCHMARKS.md` T-069). That 19-point gap is the most any pick fix can recover.

Same-gender evidence in one line: SpeakerBeam-style extractors are weakest on same-gender mixtures ([2001.08378](https://arxiv.org/pdf/2001.08378)); target confusion is the named failure and a stronger speaker encoder helps ([2204.01355](https://arxiv.org/pdf/2204.01355)); embeddingless cues cut it (WeSep accuracy above). That is an argument for USEF-style cross-attention cues, not for any streaming model we can get this week.

## 2. Cheap fixes for wrong-speaker switches in separate-then-pick (focus 2)

**2a. Window stitching / permutation alignment.** Meeting-CSS systems align each window's channel order to the previous one by minimising the summed squared difference over the overlapping frames, and use only the non-overlapping frames of the current window to save latency ([1810.03655](https://ar5iv.labs.arxiv.org/html/1810.03655): 2.4 s window, 75 % overlap, so 0.6 s hop). Dual-path CSS stitches by maximum similarity on the shared region then overlap-add ([2102.11634](https://arxiv.org/pdf/2102.11634)); RSAN compares masks on shared frames ([2110.14838](https://arxiv.org/pdf/2110.14838)). Graph-PIT notes stitching breaks when more speakers are active than output channels ([2107.14446](https://arxiv.org/pdf/2107.14446)): in a cafe with a third voice, a window's two streams may carry the target plus a mixture of the rest. We already do this once (`_follow_hop`); the cheap extension is to keep **both** streams as aligned running tracks.

**2b. Sticky decision / sequential audit.** Diarization smooths per-segment speaker posteriors with an HMM whose self-transition is large; sticky-HMM temporal smoothing "provides substantial performance gains" ([0905.2592](https://arxiv.org/pdf/0905.2592)); online systems may only use already-labelled segments ([review 2406.14464](https://arxiv.org/pdf/2406.14464)). No source gave streaming hysteresis thresholds or a latency/error trade-off, so any numbers are ours to measure. Our target never changes during a session, so a very sticky prior is legitimate.

**2c. Longer / running embedding context.** Our own T-069 numbers above show 1 s -> 2 s helps (accuracy +.06, wrong -0.4 s per 10 s). Streaming TSE papers treat the stored speaker state as the hard part: 22 hand-designed update rules (confidence-gated, oracle-activity-gated) all sit on a stability-plasticity frontier; a 41 k-parameter meta-trained memory gains 3.0 dB over the best heuristic under severe enrollment mismatch with under 5 % overhead ([2609.20463](https://arxiv.org/abs/2609.20463), code only, no weights stated). MeMo feeds the previous output back as the cue, at least +2 dB SI-SNR over its baseline ([2507.15294](https://arxiv.org/abs/2507.15294)).

**2d. Complement subtraction in doubtful windows.** Target-confusion post-filter: flag an estimate whose embedding is on the interferer's side, replace it with mixture minus estimate. SI-SDRi 13.05 (CE baseline) -> 13.88 with metric learning + post-filter ([2204.01355](https://ar5iv.labs.arxiv.org/html/2204.01355)). Caution from the same paper: with a pretrained ECAPA only 2.4 % / 6.4 % of confused samples fell beyond the equal-similarity border / 0.1 margin, so ECAPA similarity is a weak confusion detector, which matches T-200's 50/50.

## 4. Ranked top 3 (try in this order, stop at the first that moves wrong-speaker)

1. **A: alignment-first with sequential audit.** Smallest change, no new model, all pieces exist (`_follow_hop`, `margin_score`, `held`). First step (30 min): from existing per-window logs, count how many wrong windows had margin above the hold threshold. If most do, today's hold never sees them and A (or D) is exactly the fix; if most are low-margin, the hold already fired and the fault is the separator, so go to C.
2. **B: two aligned tracks, 2-3 s running embedding.** Uses the only lever our own data shows working (longer context) without raising the separator window or delay; measure ECAPA cost first.
3. **C: USEF-TSE windowed trial.** The only listed option with downloadable weights, an embeddingless cue and a published small same-gender gap. Time-box 45 min to a first MPS run, as T-203 did; drop it if the checkpoint's training data or speed rules it out.

Adoption bar (T-180's rule, `docs/BENCHMARKS.md`): wrong-speaker % does not rise, leak improves at least 3 dB, true dropouts rise at most 0.2 s; humans listen to finalists only. Everything stays behind its knob until then; nothing here changes `config/demo-team.yaml`.
